## Workflow contract

File: [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml).

| Item            | Configuration                                                                       |
| --------------- | ----------------------------------------------------------------------------------- |
| Workflow name   | `CI`                                                                                |
| Pull requests   | `pull_request` targeting `main`, default opened/synchronize/reopened activity types |
| Pushes          | `push` to `main` only                                                               |
| Manual          | `workflow_dispatch`; available after the workflow reaches the default branch        |
| Job             | `windows-quality`, display name **Windows quality checks**                          |
| Runner          | GitHub-hosted `windows-2025`, x64; no OS matrix                                     |
| Shell/directory | PowerShell (`pwsh`), `apps/desktop` for every `run` step                            |
| Timeout         | 45 minutes                                                                          |
| Permissions     | `contents: read`; all unspecified token permissions disabled                        |
| Checkout        | Default event ref, shallow checkout; `persist-credentials: false`                   |
| Concurrency     | Workflow + event + ref; cancel older runs in the same group                         |
| Distribution    | None: no releases, artifacts, installers, signing, deployment, or secrets           |

There are no path filters, so documentation-only changes also exercise the quality job. Feature-branch pushes are not triggers; an open PR targeting `main` validates those commits. Event-separated concurrency preserves push and manual runs independently while cancelling superseded runs of the same event/ref.

## Checks and compilation order

Commands below run from `apps/desktop`, in workflow order after setup:

| Command                                                     | Check                                                                                                                                        |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm install --frozen-lockfile`                            | Exact existing pnpm resolution                                                                                                               |
| `pnpm typecheck`                                            | Frontend and Vite/Vitest TypeScript configuration                                                                                            |
| `pnpm lint`                                                 | ESLint with `--max-warnings 0`                                                                                                               |
| `pnpm format:check`                                         | Prettier and `cargo fmt --check`                                                                                                             |
| `pnpm exec prettier --check ../../.github/workflows/ci.yml` | Workflow formatting outside the desktop package's normal formatting scope                                                                    |
| `pnpm test`                                                 | Frontend unit tests                                                                                                                          |
| `pnpm desktop:build`                                        | `tauri build --no-bundle -- --locked`; production frontend through `beforeBuildCommand: pnpm build`, then release Windows native compilation |
| `pnpm lint:rust`                                            | `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings`                                                    |
| `pnpm test:rust`                                            | `cargo test --manifest-path src-tauri/Cargo.toml --locked`                                                                                   |

The native build runs before Clippy/tests so a clean checkout has `dist/` for Tauri's release-context asset embedding. CI does not run `pnpm build` separately: the Tauri hook already executes TypeScript checks and Vite's production build. The explicit earlier typecheck gives quicker feedback; no extra frontend asset compilation is added. Clippy/tests share the job's local Cargo target directory; development/test and optimized release compilation still require different profiles. There is no second standalone `cargo build`.

Cargo's default test selection includes unit, integration, and documentation tests. The bootstrap currently has one Rust unit contract test and no dedicated integration-test files; this workflow does not invent integration coverage. Future integration tests selected by the existing command will run automatically.

## Cache boundaries

- pnpm: the directory returned by `pnpm store path`, keyed by runner OS/architecture, Node version, `package.json`, and `pnpm-lock.yaml`. No `node_modules` or frontend `dist` cache.
- Cargo: only `~/.cargo/registry/index`, `~/.cargo/registry/cache`, and `~/.cargo/git/db`, keyed by OS/architecture, Rust toolchain, and `Cargo.lock`.
- No `target/`, application executable, installer, database, benchmark dataset, personal file, or complete Cargo home is cached. No broad fallback restore keys are configured.
- Caches speed dependency downloads; they do not replace frozen/locked installation or successful checks. Cold runners still compile native dependencies.
