## Investigation and bounded conclusion

Reviewed [ManualArtwork.test.tsx](../../apps/desktop/src/features/library/ManualArtwork.test.tsx), [ManualEditor.tsx](../../apps/desktop/src/features/library/ManualEditor.tsx), [Thumbnail.tsx](../../apps/desktop/src/features/library/Thumbnail.tsx), the [artwork queue](../../apps/desktop/src/features/library/artwork.ts), [queue/Thumbnail tests](../../apps/desktop/src/features/library/artwork.test.tsx), the [request gate](../../apps/desktop/src/features/library/requestGate.ts), [Vitest configuration](../../apps/desktop/vitest.config.ts), [package scripts](../../apps/desktop/package.json), TypeScript configuration and the installed React Testing Library async wrapper. There are exactly six consumers of `observeArtwork()`, all in the changed test file. Vitest specifies jsdom, the test-file include pattern and `clearMocks`; there are no configured setup files or custom Testing Library wrappers.

The confirmed test defect is an implicit readiness assumption: finding the artwork region or replacement/choose button proves DOM availability, but does not guarantee completion of `Thumbnail`'s passive subscription effect. Manual details arrive through an asynchronous request gate. React can commit the preview DOM before running that effect, and the Testing Library DOM query does not explicitly synchronize on registration. Its microtask-draining wrapper is not a registration barrier. The mock captures the callback synchronously when `subscribe` actually runs. The historical empty array is consistent with this ordering gap.

No production defect was found in the reviewed registration/cleanup paths. `Thumbnail` invalidates its local `current` flag before calling its release function; obsolete callbacks cannot update that consumer. Preview keys change on bounded refreshes, including same-revision refreshes. Selection changes suppress the old preview, and confirmed mutations retire it while details refresh. Queue release removes the exact subscriber; `clear()` removes listeners and advances the cache epoch without prematurely freeing active native capacity. The direct `Thumbnail` tests render/rerender synchronously within Testing Library's `act` wrapper and retain their unsubscribe and stale-callback assertions unchanged.

The original focused suite also passed locally before editing. There is no captured CI scheduler trace or deterministic local reproduction of the historical interleaving. This investigation confirms the unsafe test assumption and removes it; it does not prove that every possible cause of an intermittent failure has been eliminated. Successful repetitions alone do not definitively resolve the historical failure.

## Exact correction and assertions

Only [ManualArtwork.test.tsx](../../apps/desktop/src/features/library/ManualArtwork.test.tsx) changes executable test source: **25 insertions, nine deletions**. `observeArtwork()` now returns the original append-only `listeners` array plus this method:

```ts
async waitForSubscriptions(count: number) {
  // The preview DOM can commit before Thumbnail's subscription effect runs.
  await waitFor(() => expect(listeners).toHaveLength(count));
}
```

All six consumers destructure both values. Twelve calls wait for exact registration counts at the relevant boundaries; two replace existing inline exact-length waits. No callback is invoked inside the wait. The original indexed listener references remain intact, including intentionally obsolete ones. No filtering, array clearing, replacement by the latest listener, optional callback invocation or relaxed minimum-count assertion is introduced.
