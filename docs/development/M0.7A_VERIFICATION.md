# M0.7A — Renderer layout profiling and optimization

Session verification date: 2026-10-27. **M0.7A is complete within the renderer investigation scope.** First-use Japanese font work contributes to the reproduced sort stall; the final title-scoped fallback reduces measured Layout/task/frame maxima while other timings remain mixed. The wider M0 gate remains open. M0.7B/M0.7C, SQL changes, integrations and real game files are outside scope. No commit or push is authorized or performed.

The initial working tree was clean at `d6e028d`, the merge of M0.6 (`f092843`). Reviewed root AGENTS, README, PROJECT_STATUS, ROADMAP, PRD/TAS performance requirements, ADR-004, M0.3–M0.6 reports, Details View/CSS/controls/rows/diagnostics/virtualizer and native drivers. ## Reproduction and measurement method

Use the existing generator-v1, seed-42, schema-1 fixtures at 15,000 and 25,000 games. Windows/Ryzen 5 4500/64-GB reference machine; E: NVMe SSD, retained OS filesystem caches. Fresh independently generated job databases, derived-artwork caches and WebView profiles per process. Workload seed 20261026, default two resource workers, normal two artwork workers, unthrottled admission. No real installation or personal library is opened. Normal Windows/IDE activity remains uncontrolled. No tests/builds run during quantitative collection.

The original M0.6 prelude matters: bounded native query/artwork probes, Library remount, text/combined criteria, reset, installed and not-installed transitions, then **all installations → release-date descending**, without visiting the title-sorted tail first. Record first-use and subsequent transitions separately. Check the actual ordered row IDs against the unchanged native 100-row query, 38-pixel rows, 48×27 placeholders, scroll reset and cleared selection. Follow with rapid scrolling and selected loaded End results.

The added bounded expected-row IPC query runs before tracing in both artifacts and warms that native page path equally; it never inserts text into the DOM. Consequently the IPC/commit values below are matched between these two artifacts, not a direct replacement for the differently instrumented historical M0.6 matrix. Glyph first use remains cold until the measured transition.

Example from repository root, with built `job-fixtures.exe` and existing artwork roots:

```powershell
./benchmarks/background.ps1 `
  -DatabaseDirectory E:\dev\game-manager\benchmarks\data\m0.2-2026-10-25-01 `
  -ArtworkDirectory E:\dev\game-manager\benchmarks\data `
  -ResultsDirectory E:\dev\game-manager\benchmarks\results\m0.7a-example `
  -Sizes @(15000,25000) -Cases mixed2 -Iterations 5 -TraceSort `
  -SortRepetitions 2 `
  -BenchmarkExecutable E:\dev\game-manager\benchmarks\results\m0.6-artifacts-final\game-manager.exe
```

Always use a new output directory. Repeat with the retained candidate, alternating artifact order across fresh processes. `-ClosedDiagnostics` and `-Cases mixed0` provide observer/artwork controls; mixed0 keeps the same mixed workload including its procedural resize. Omit `-TraceSort` for matched untraced measurements. Periodic WMI memory sampling stays disabled; final process-tree private bytes are taken after frame capture. These are point samples, not a memory bound.

`-LayoutVariants` selects **temporary benchmark-only CDP overrides**: `baseline`, `blockMain`, `gridStart`, `minHeight`, `fixedControls`, `blockControls`, `stableScrollbar`, `fixedPanel`, `explicitCjk`, `explicitResolved`, `noLegibility`, `warmLatin`, `warmCjk`. Reverse order within repeated processes, but use fresh processes to assess first-use effects. Hidden glyph warmups are experiments, not shipped startup work.

`node benchmarks/summarize-layout.mjs RESULTS_DIRECTORY` derives nearest-rank distributions from raw renderer traces and trial records. Layout wall time and renderer thread CPU are distinct; nested FunctionCall and Layout spans overlap and are not added together. CDP ScriptDuration is recorded separately. Long-task observation covers renderer main-thread work, including native layout; it does not establish JavaScript function execution as the cause. rAF intervals include idle/automation time and do not measure achieved FPS or presentation latency. Criteria-to-visible is the existing React commit metric, which can precede an expensive subsequent Layout.

Per-trial frame arrays are independent of the existing 4,096-entry whole-run ring, so a full ring cannot silently produce empty transition samples. Parser tests preserve rare tails, separate CPU/wall time, restrict events to the marked renderer thread and report absent CPU instrumentation as unavailable.

## Investigation evidence and cause

1. `m0.7a-experiments-01`: a new deep-first exploratory driver ran eight CSS variants three times at 15,000. It did **not** reproduce a long task; its initial baseline's largest Layout was 8.179 ms. It navigates End before measuring, rendering Japanese titles at the title-sorted tail. This is a failed cold-path reproduction, not evidence that the original issue disappeared.
2. `m0.7a-original-driver-01`: the retained M0.6 artifact and original driver reproduced an **80-ms task**, with **74.755-ms Layout / 68.602-ms CPU**, 255 dirty / 412 total objects.
3. `m0.7a-original-experiments-01` failed because inline experimental styles were blocked by the production CSP. It is excluded from optimization comparisons. Experiments now use CDP stylesheets and verify the actual stylesheet text. No CSP relaxation was made.
4. `m0.7a-original-experiments-02`: eight CSS candidates × three transitions retained the expensive first baseline (87.954-ms maximum Layout), while later baselines and unrelated CSS candidates were much faster. The first-use/order confound prevents crediting flex/grid/scrollbar changes. No such changes ship.
5. `m0.7a-font-warm-latin`: a Latin-only hidden title forced 2.5 ms of layout; the subsequent sort still recorded an 84-ms task.
6. `m0.7a-font-warmCjk-01`: a hidden `星の` title forced **85.6 ms** of layout; its trace's expensive Layout was **85.234 ms** with only **five dirty objects**. The subsequent sort's maximum Layout was 12.384 ms, with no observed long task. CDP identified **Noto Sans JP / Noto-Sans-JP-Medium** for those two glyphs. This moved the cost; warming is not a performance fix.
7. `m0.7a-font-baseline-01`: a fresh baseline again recorded a 79-ms sort task. CDP identified Segoe UI Semibold for the Latin characters and Noto Sans JP for the Japanese characters in the same title.
8. `m0.7a-font-noLegibility-01`: `text-rendering: auto` still recorded an 85-ms task. `m0.7a-font-explicitCjk-01` selected Yu Gothic UI Semibold instead, with a 44.896-ms maximum Layout and a 50-ms task; it changes the chosen Japanese face and is not the shipped correction.
9. `m0.7a-font-explicitResolved-01`: explicitly naming the already-selected Noto Sans JP before generic fallbacks retained the same Japanese face and reduced the first maximum Layout to 28.646 ms in this exploratory capture. Repeated artifact comparisons below determine the final result.

The controlled evidence isolates the **first-use Japanese font path** as a major contributor to the reproduced transition stall. The release-sorted first mounted window introduces `星の Islands: Origins 9`; a prior End visit has already rendered Japanese titles and masks that cold path. An expensive five-dirty-object probe shows that hundreds of dirty document objects are not necessary for the font-related stall. Exact native font lookup, file initialization and shaping subdivisions were not stack-profiled; do not attribute every microsecond to one internal font function.

The final correction scopes optional local `Noto Sans JP` after the existing Segoe families and before generic system fallbacks **to `.game-title`**. It adds no font asset, download, package or required installed font. When absent, the existing generic fallback path remains. It preserves the observed Latin/Japanese title faces and leaves the interface/placeholder font stack unchanged. It does not prevent all document invalidation, change containment, cache geometry, row measurement, selection or scrolling, or guarantee performance for every script/font configuration.

### Process memory and measurement limitations

Legacy process-tree private-byte points from the three primary processes per artifact/size were median / maximum: 15,000 baseline 302.328 / 304.648 MiB, candidate 304.512 / 304.996 MiB; 25,000 baseline 310.359 / 310.801 MiB, candidate 304.250 / 307.313 MiB. These are final points after safety work, not peak/steady-state bounds or proof of a memory improvement.

The 15,000/mixed0/hidden-diagnostics candidate control recorded **718.230 MiB across 12 processes**, versus 294.742 MiB across eight in its baseline control. This outlier is retained unchanged. Native private bytes were about 8.5 MiB in both; sort-time browser heaps were about 9.72 MB in both, and each ran one mixed job before cancellation. No per-PID data was stored by the old collector, so the extra processes and their contribution cannot be retrospectively attributed to the application or dismissed as a leak-free pass.

Review found a measurement weakness: traversing ParentProcessId alone accepts older orphan processes if Windows reuses a departed parent's PID. The shared sampler now checks creation order, checks that live process identity still matches the CIM snapshot, and records per-PID creation times/private bytes. Deterministic ancestry/missing-root tests and a live serialization check pass. The first repeat exposed a PowerShell hashtable aggregation incompatibility after UI collection; it is excluded, corrected with typed property-bearing records and rerun.

`m0.7a-memory-repeat-02-{baseline,candidate}` repeats 15,000/mixed0/hidden diagnostics with the corrected sampler: **279.195 MiB baseline / 287.773 MiB candidate, seven age-validated processes each**, with full per-PID records. The UI/job/audit probes pass. This does not reproduce the 718-MiB point and does not identify its historical extra processes. No memory reduction, hard bound, long-session stability or resolved outlier is claimed. The sampler change happens after frame capture and does not alter the paired renderer instrumentation or application binary.
