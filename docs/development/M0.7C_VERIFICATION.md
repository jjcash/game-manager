# M0.7C — Integrated performance and resource validation

Verification date: 2026-10-27. **M0.7C investigation complete within the tested synthetic scope; the wider M0 performance gate remains open.** No commit, push or post-M0 work is authorized or performed.

## Executive summary

Deep-page costs reproduce, including a smaller real row-arrival regression in repeated M0.7A/M0.7B controls; polling and sequential overscan-page retrieval add separate delay. Long memory runs show finite late-session stabilization and substantial idle reclamation, with retained memory and leak freedom still unproven. Whole-process warm release-scale startup misses one second. Real HDD and bounded disk contention are measured; lower RAM, other physical scaling, controlled OS-cold startup and actual presentation remain unverified. Relationship-heavy derivatives fail latency targets despite improved total count-plus-page time. All applicable automated/native checks pass; passing correctness assertions does not make performance budgets pass.

M0.7B's ordered entry-set strategy, arbitrary-offset pagination, title-scoped optional Japanese fallback, two artwork workers and unthrottled default admission are retained. New instrumentation distinguishes browser-local loaded-row arrival from subsequent rAF opportunities. These opportunities are not actual compositor/GPU presentation.

The actual captured current selection SQL is:

```sql
SELECT g.id FROM games g WHERE 1=1
AND NOT ((g.id IN (
  SELECT e.game_id FROM library_entries e WHERE e.id IN (
    SELECT i.entry_id FROM game_installations i
    WHERE i.detection_state='present'
  )
)) IS TRUE)
ORDER BY g.sort_title ASC, g.id ASC LIMIT ? OFFSET ?
```

Bindings are limit 100 and the exact offsets above; count/page use the same predicate. Raw JSON retains the **complete actual count, selection and full projection SQL**, requests and plans. The selection plan scans `ix_games_sort`, builds installation-entry/game membership lists through `ix_installations_entry` and the entry primary key, and creates Bloom filters. Count scans canonical games with those lists. Full-page plans materialize the bounded ID page, look up canonical summaries, run indexed membership/copy/source projections and bounded final ordering; DISTINCT/source projection uses temporary B-trees. No `ANALYZE`, index or schema changes occur. This plan supports work proportional to membership construction and ordered candidates skipped before a deep offset; exact SQLite opcode/CPU attribution is not measured.

Current diagnostic installed count+page p95 remains **44.886 first / 62.306 deep ms** at release versus old correlated **111.546 / 168.742**, and **74.456 / 91.527** at stress versus **247.199 / 239.556**. Not-installed deep combined p95 is **53.494 / 90.442** versus **71.228 / 171.434**. A narrower page can still regress while the full operation improves. No alternative demonstrates an overall benefit sufficient to reverse M0.7B.

Production remains a bounded materialized ID page followed by canonical summary projection. The membership set is statement-local; deep OFFSET scans ordered canonical candidates up to the requested match count. It supports arbitrary virtualizer jumps and exact complements rather than constant-time tail retrieval.

Timing interpretation:

- Diagnostic count, ID selection, full-page and projection timers use SQLx raw-row delivery on bundled SQLite. They include preparation/worker delivery/decoding, not only SQLite VM execution. Split selection/projection are extra diagnostic statements and must not be added to the independently measured full statement.
- Backend page service includes pool acquisition, query delivery and DTO construction. Metadata `queryMs` covers its filtered count path but ends before the additional global counts/source-options work.
- Browser IPC times include the complete command and serialization/bridge/browser work. Metadata IPC minus filtered-count service therefore includes additional backend queries, not just transport overhead. Separate percentiles cannot be added or subtracted into a causal decomposition.
- Supplemental CDP network intervals cover actual local POST request through protocol completion, with bounded response-body readback for backend timings. Tauri's invoke is immutable and is not wrapped. These protocol intervals exclude caller setup, possible preflight, JS parsing and callback delivery; full invoke timers remain separate. Headers/authentication keys/full row bodies are not retained. Network buffers/readbacks add observer overhead and are not mixed into primary timings.
- Existing criteria-to-visible metrics are React layout-effect commits. Production React has no Profiler render-duration samples. Library commit, loaded-row arrival, rAF, Layout, Paint and presentation remain different boundaries.

No plan alternative, index, keyset pagination, schema change or reusable count cache is adopted without a measured overall advantage and preserved semantics.
