# M1.3 — Steam preview: security stop

Date: 2026-10-28. **M1.3 is not implemented or verified.** No discovery action, production reader, Steam IPC, approval grant, preview, migration or importer has been added. The security stop rule applies because approved-root confinement has not been demonstrated. This report is an investigation record, not a completed milestone verification.

## Baseline and findings

The working branch started clean at `7ed43ed2e91c21c2ae4d82c14e0675640c17d623`, the M1.2 merge, also the local `main` head. M1.2's parser, path rules and simulated snapshot checks live in integration-test support; they do not open files or prove native confinement. The production command registration and main-window capability contain no Steam discovery commands. M1.1's application database remains schema v2; M0 remains conditionally closed with ADR-007 exceptions E1–E5.

The critical unresolved issue is an implementation and verification gap, not a finding that safe Windows confinement is impossible. Microsoft documents directory-relative names in [user-mode NtCreateFile](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), and [OBJECT_ATTRIBUTES](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_object_attributes) describes `OBJ_DONT_REPARSE`. The former's attribute description lists zero or `OBJ_CASE_INSENSITIVE`; these pages alone do not establish the complete application-specific guarantee for approval acquisition, reparse and rename races. The approved root's own acquisition and identity, local-volume policy, hard links, file replacement and the interaction of held handles with concurrent changes also require a reviewed design and actual native tests. A lexical check or canonicalize-and-reopen is insufficient.

## Verification and remaining work

No production reader exists to subject to the required sentinel, reparse, hard-link, concurrent replacement, cancellation or resource tests. No real Steam client or personal data was accessed; live compatibility is unverified. No preview screenshots, performance measurements, database byte-invariance experiment or M1.3 native smoke are available. Existing baseline results in the M1.1 and M1.2 reports remain historical results, not tests of this milestone. No new Steam files or application database writes were performed by this investigation.

The baseline command `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --locked --test steam_discovery` passed all 17 synthetic contract tests. Rust was made available through a session-only PATH adjustment. These tests do not exercise a Windows reader. The remaining requested quality and native checks were not run because no implementation was produced.

The next step is to design and implement an isolated, fail-closed Windows reader with native directory identity and handle-relative access, then prove its behavior using disposable fixtures, including external sentinel non-access and concurrent attacks, before registering any production discovery command. Review the platform API contract and supported filesystem/version scope; reject cases whose safety cannot be established. Once that gate passes, implement the bounded session, approvals, parser integration and preview, and run the full requested quality, isolation and performance checks. Persistent importing remains a separate later milestone.
